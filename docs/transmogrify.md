# Transmogrify (`TRANSMOGRIFY`, 1.3.0)

The Transmog Master changes a character's equipment appearances. Masters stand near the smiths in Skaldholm, Nacrehold, Asterion and Veyrroot Heartwood. The character keeps its real equipment, inventory, stats, refinement, durability and set bonuses.

## Wardrobe and saved choices

`Character.wardrobe` contains a permanent set of equipment catalog IDs (`unlocked`), a map of slot choices (`slots`), and a one-way login migration flag (`migrated`). Missing fields default to empty for existing saves. The first load collects equipped pieces, positive bag stacks and positive bank stacks. `Character::add_item` collects subsequent acquisitions; trade's direct stack transfer has its own unlock call. Equipping/synchronizing owned gear also collects it. Selling, consuming, banking or trading away a piece never removes its wardrobe entry. Rebirth clones the wardrobe and choices without resetting either.

The seven visible slots are `chest`, `hands` (weapon), `headgear`, `shoulders`, `gloves`, `pants` and `cloak`. Necklace and rings cannot be selected. A choice is an unlocked catalog ID of the same kind and the character's class or class-neutral gear. Required level is deliberately ignored for appearances. GM rarity still requires a GM character. `hide` is accepted only for headgear, shoulders and cloak; `real` removes a choice.

Choices belong to slots and survive upgrades and unequipping. Empty slots always render nothing. Rendering validates saved choices again, so an invalid or no-longer-authorized choice cannot draw. Other players, seam observers, the paper-doll figure and Inspect see the rendered appearance; the equipment icons and stats describe the actual pieces.

## Fees and protocol

Each changed non-real choice costs `500 + floor((clamp(level, 1, 99) - 1) * 19500 / 98)` copper: 5 silver at level 1, 1 gold 2 silver 50 copper at level 50, and 2 gold at level 99. Hide costs the same. Existing identical choices and reverts cost zero.

`{"type":"transmogrify","npc":"city_transmog","changes":{"chest":"<item id>","headgear":"hide"}}` submits a batch of up to seven slots. The client never supplies prices, levels, class or unlock evidence. The authoritative handler checks life, combat, mounting, travel, cutscenes, trade/PvP state, the actual NPC's service and distance (2.8 tiles), then validates and charges the entire batch on a cloned character. It saves that copy before publishing it. A failed validation, insufficient purse or failed save changes nothing.

A master's dialogue includes `wardrobe`, `transmogs`, `transmogPrice` and the GM flag. Owner snapshots include `equippedLook` (the real equipment look) and `transmogs` (saved slot choices). `look` is generated by `Character::appearance_look`; it never replaces `Character.look`, which also drives chest/weapon stats. `visibility::OWN_ONLY` strips the real look and choice map from other viewers. The full collection is sent only when speaking to a master, not every snapshot. Inspect explicitly exposes only active transmogs alongside actual item IDs, stats and the visible look.

## Client and world pipeline

`client/transmog.js` owns the seven selectors, localized search, live animated preview, combined fee and single Apply request. Requests stay disabled until a dialogue reply or refusal. Closing the NPC window releases the animation loop and invalidates pending sprite loads. Selecting a cosmetic item changes only a preview look clone. Inventory gets `equippedLook` instead of the rendered look; its cached quantities, worn-copy resolution, equipment selection and icons remain based on the real gear. A violet corner marker and tooltip line describe the slot appearance in bags, paper-doll and Inspect.

`scripts/transmog_npcs.py` is the final NPC overlay in `sync-world.cjs`. It adds only four NPCs, with deterministic reachable positions near the existing smiths, and reuses their existing local artwork. It moves no people, objects, quests, roads, monsters, portals, fishing waters or seasonal content. The normal complete sync remains the source of `client/world.js` and the embedded map.

Swedish is handwritten in `sv-translations.txt` and `sv-template-translations.txt`; the version is kept in `sv-keep.txt`. The new client module is in the Swedish harvest list.

## Focused validation

- `cargo test transmog`: acquisition, one-time migration and actual store load, persistence, all seven slots on all five classes, stats and real equipment preservation, empty slots, upgrade/unequip behavior, low-level appearances, fees, free reverts, atomic invalid batches, class/slot/GM guards, authoritative range/state/service checks, Inspect and snapshot privacy, trade delivery and four-city NPC collision checks.
- `node tests/transmog.cjs` and `--mutations`: production preview and controls, batch payloads, affordability, real inventory quantities/icons/tooltips, markers and refusal handling. Faults cover empty-slot rendering, revert fees, class eligibility, hide eligibility, icon replacement and request contents.
- `python3 tests/transmog-rust-mutations.py`: seven changes to the actual Rust sources, checking unlocks, empty slots, free reverts, atomic refusal, trade delivery, store migration and snapshot privacy. It restores the original bytes after each fault; rerun the focused tests on the restored tree.
- `python3 tests/transmog-data.py`: complete pre-feature world preservation, overlay idempotence, art preservation, reachable master positions and client-map equality. `MUTATE=preserve|reach` must fail.
- `node tests/transmog-protocol.cjs`: real two-player private controller, appearance/stat separation, Inspect/privacy, atomic rejection, upgrading and unequipping, reconnect and process restart, and free reverting with an empty purse.
- `tests/transmog-ui.cjs`: private real-client desktop/phone flow, an unlocked level-95 appearance on a level-1 character after the original item is gone, combined fees, hidden headgear, stat preservation, real-item markers/tooltips and free reverts. `MUTATE=1` removes the fee calculation and must fail. Browser execution requires the owner's explicit exception to the production-host restriction and the unchanged bounded runner.

This feature branch is staged work. Publishing requires coordinated client and executable deployment; the public game must only be restarted after fresh owner approval.
