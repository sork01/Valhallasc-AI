# Mailboxes

Owner requirements (2026-11-03): players can mail messages, gold and **unbound** items to other players; every city and hub has an accessible mailbox. A party loot hand-off window never makes bound class gear eligible for mail.

Implementation defaults (chosen for this implementation, not additional owner decisions):

- Recipients are existing uniquely named characters, including offline guests and account characters. Exact names use the store's Unicode name key; lookup returns only the canonical name. Self, unresolved legacy duplicate names, hires and ambient adventurers are refused. Other characters on the same account are allowed.
- Delivery is immediate and free. All requests require a living, dismounted, non-travelling character out of combat and within 2.8 tiles of a mailbox in the same zone. Active trades block mail transactions.
- One letter has a subject of 1–80 characters, a message of up to 2,000 characters, up to six attachment entries, and carried gold up to the existing u32 balance limit. Each entry is one positive-quantity stack, or one explicitly selected loose gear copy. Duplicate stack/copy entries are refused. Text is plain text; control characters except newline/tab in the message are refused.
- Class gear, starter/GM gear, mount licences, quest items, equipped gear, fitted bags and unknown items are ineligible. Class-neutral loose gear, materials, potions, food and loose bags are eligible under the existing trade restrictions. Gear keeps rolled stats, rarity, rank and wear; it receives a fresh owner-local copy ID on collection. Trade windows are cleared.
- An inbox holds up to 100 undeleted letters. A sender can create up to 30 letters per hour. Returns bypass those caps so belongings can always be returned. The server keeps request receipts after deletion; retrying a send with its original request ID never charges or delivers twice.
- Opening lists inbox letters; reading marks one read. Collect takes **all** attachments and gold in one transaction. If any attachment cannot fit or any balance/stack would overflow, nothing moves. An already-collected letter can be collected again harmlessly.
- Letters never expire. Delete is allowed only with no uncollected attachments. An uncollected letter can instead be returned once to its original sender's inbox, with all attachments still in escrow; a returned letter must be collected before deletion. If the sender no longer exists, return is refused and collection stays available. Character deletion is refused while it is sender or recipient of any pending attachment, preserving return identity. Empty letters can be deleted normally.
- SQLite mail/attachment state and the affected character save commit in one transaction before memory changes or success replies. Failed saves roll back everything. Offline recipients are not rewritten. Normal saves cannot resurrect escrow or duplicate claims. Read, collect, delete and return always scope the row to the authenticated recipient ID.
- Unread counts appear beside World Menu → Mail and update on login, receipt, read and return. The menu opens a nearby mailbox only. Inbox, compose and reading share one scalable, phone-friendly window; English/Swedish labels are provided. Player-written names/messages are not translated.

World placement is generated by `scripts/mailboxes.py` after all layout overlays in `sync-world.cjs`. Its coverage derives from cities plus hub services/travel stops in the actual map; `world/mailboxes.txt` records each location and service anchor. Mailboxes are stationary interactable NPC records with a `mail` offer and native PixelFlow prop artwork. They have no collision and preserve all existing services and routes.

Validation and private release status are recorded in `docs/mailboxes-validation.md`.

Protocol examples (every action rechecks the mailbox):

```json
{"type":"mail","npc":"mailbox_0_alderhaven","request":{"op":"open"}}
{"type":"mail","npc":"mailbox_0_alderhaven","request":{"op":"lookup","name":"Sork"}}
{"type":"mail","npc":"mailbox_0_alderhaven","request":{"op":"send","request":"a-fresh-uuid-receipt","recipient":"Sork","subject":"A gift","body":"Hello!","gold":10,"attachments":[{"item":"slime_gel","quantity":2}]}}
{"type":"mail","npc":"mailbox_0_alderhaven","request":{"op":"collect","id":1}}
```

`read`, `return` and `delete` also name the inbox letter's numeric `id`. Gear attachments include `copy` and quantity 1. Replies are `type: mail`, the mailbox `npc`, `ok` and localized `notice`; success also supplies the authoritative inbox, gold/inventory/copy state and attachment choices with refusal reasons. `found` is only an exact public character name; `sent` is a persisted send receipt ID. `mail_unread` updates the owner's badge; the owner also receives `mailUnread` in their private snapshot. Other viewers do not receive this count.
