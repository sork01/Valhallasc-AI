# Treasure chest rules

These settle `CHEST-RULES` in [TODO.md](../TODO.md). `CHEST-SERVER`, `CHEST-ANNOUNCE`, `CHEST-ART`, `CHEST-CLIENT` and `CHEST-CHECK` implement them. Chests are **runtime state**: never saved, and a restart clears them.

## Constants

Defined once in a new `server/src/world/chests.rs` and imported by tests; no other file may repeat the numbers.

| Constant | Value | Meaning |
| --- | ---: | --- |
| `CHEST_ROLL_INTERVAL` | 120 s | One roll per area per interval. |
| `CHEST_SPAWN_CHANCE` | 0.10 | Chance that a roll creates a chest. |
| `CHEST_LIFETIME` | 180 s | Time before an unopened chest despawns. |
| `CHEST_MAX_PER_AREA` | 1 | A roll while a chest is up does nothing (not banked). |
| `CHEST_OPEN_RANGE` | 2.0 tiles | Distance from the chest centre to open it. |
| `CHEST_MIN_ARRIVAL_DISTANCE` | 14 tiles | Minimum walking distance from the arrival point and from every portal. |
| `CHEST_PLACEMENT_TRIES` | 40 | Candidate tiles tried before the roll is skipped. |

The expected rate is one chest per 20 minutes of occupied time per area.

## What an "area" is

- **Open world:** one area per map that has monsters, one roll per map. Eligibility is derived from `world/map.txt` (a map with a non-empty `slimes` list and no `copies`). Cities and enemy-free maps never roll.
- **Dungeon:** one area per **running party copy**. A copy rolls only while it is `active` (someone is inside and the enemies have been touched). Its timer starts when the copy activates, resets when the copy resets, and stops when it closes. A copy that is `cleared` stops rolling (the final boss's loot is the prize), and a roll is skipped while any boss in the copy is engaged.
- **Occupied only.** A roll happens only while at least one living player is in the area, so nobody ever misses a chest they could not see. The timer is a countdown stored on the area, started when the area first becomes occupied: walking into an empty zone never causes an immediate roll, and a zone that empties pauses (does not reset) its countdown.
- The authoritative eligibility list is [chest-eligibility.txt](chest-eligibility.txt), generated by `python3 scripts/chest_zones.py --write` and verified by `--check`. At the time of writing: 19 open zones, 16 dungeons with 4 copies each, 6 maps that never roll.

## Placement

The server picks a tile from the copy's own collision grid, seeded from the world RNG so tests are repeatable:

1. Flood-fill the walkable tiles from the area's arrival point. Sealed doors, gated portals and boss-gated passages count as walls, so a dungeon chest can never sit behind a door the party has not opened.
2. Keep tiles whose walking distance from the arrival point is at least `CHEST_MIN_ARRIVAL_DISTANCE`.
3. Reject any tile within 3 tiles of a monster home, NPC, portal, object obstacle, another drop or a player, and any tile inside a boss arena. In a dungeon the tile must lie inside one of the map's `rooms`.
4. In a dungeon, also reject tiles in the final boss's room and in any room containing a living boss.
5. Try up to `CHEST_PLACEMENT_TRIES` random candidates. If none fits, the roll is skipped and logged.

## Contents

A chest holds **one gold pile, one material stack, two equipment rolls and one orange check**. Nothing is rolled until it is opened, so the drop table in force is the one at the moment of opening.

- **Gold:** 5 times the average kill gold of the area's monster kinds.
- **Material:** 3–5 of the material for a monster kind picked from the area's spawns (`items::material(kind)`).
- **Equipment (two independent rolls):** `items::equipment_of_rarity` at the area's top rolled level, with the rarity ladder gray 62%, green 30%, blue 7.5%, purple 0.5%. Starter, set and orange pieces are never chosen by these rolls. A chest therefore beats an ordinary kill on average but never reaches a boss's guaranteed blue pools.
- **Orange:** one independent 0.1% roll per chest, using the same orange pool and stat roll as the per-kill orange drop. This is the only orange chance; it is not repeated per item.
- **Dungeon set piece:** a dungeon chest has one extra 6% roll for a piece from **that dungeon's** exclusive set (its `source`), blue only. The purple chance on it comes from `DROP-EPIC-RULES` when that lands, applied to this roll like any other set piece. A boss kill still guarantees two blue set pools, so a chest cannot beat a boss. Outdoor chests never contain set pieces.
- **Bags** do not appear in chests.

## Who may open it

- Anyone in the area within `CHEST_OPEN_RANGE` and alive may open it, first to click wins; a second request fails with "Someone already opened this chest."
- The contents are an ordinary shared drop for the opener's party: they are placed on the ground at the chest with `loot_drop`, so the existing group rules apply. Gray gear, materials and gold use round robin or the shared pile; green and better is rolled for with Need/Greed. A solo opener owns everything.
- A full bag never loses an item: the drops stay on the ground like any other loot, with the normal 60-second lifetime.
- A dungeon chest exists only in its own copy and is visible only to the heroes in that copy. Closing or resetting the copy removes its chest without a message.

## Messages

- On spawn, to everyone in the area: "A treasure chest has appeared! It will vanish in 3 minutes." No direction hint, but the chest carries a countdown for anyone who finds it (`CHEST-CLIENT`).
- On open: "<name> opened the treasure chest." On despawn with nobody opening it: "The treasure chest has vanished."
- Players arriving later see the chest in their snapshot with its remaining seconds, and receive the spawn message once.

## World-map marker

None. The point is to search, so chests appear neither on the minimap nor on the world map.

## Verification hooks for `CHEST-CHECK`

- A test-only knob (`VALHALLA_TEST_COMMANDS=1`) shortens the interval and forces the roll, the same way the other debug commands skip only time.
- Seeded rolls over many intervals must average 10% within a stated tolerance.
- The eligibility test runs `scripts/chest_zones.py --check` and compares the Rust-side list with the file.
