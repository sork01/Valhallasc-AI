# Weather rules

These settle `WEATHER-RULES` in [TODO.md](../TODO.md). `WEATHER-SERVER` implements the state, `WEATHER-RAIN`, `WEATHER-SNOW` and `WEATHER-OTHER` draw it, `WEATHER-INSIDE` handles doors, `WEATHER-AUDIO` and `WEATHER-UI` finish it and `WEATHER-CHECK` verifies it. It builds on the world clock in [day-night.md](day-night.md).

Implementation: `scripts/weather_zones.py --write` generates both the readable zone table and `world/weather.txt`, which `server/src/world/weather.rs` embeds. Six four-minute slots form a cycle: 2–5 clear slots followed by 4–1 weather slots (weighted to 55% clear). The seed is the persistent day-night epoch. Snapshots carry `weather`, including the current type, intensity, wind variant, seconds remaining, elapsed seconds and indoor state. Yearwheel snapshots additionally carry four seasonal states; the client selects the quadrant. A GM or private test world can send `set_weather`, which adds a transient override. `client/weather.js` draws all weather types with one-second transitions (three seconds between Yearwheel seasons). `client/game.js` synthesizes rain, wind and thunder through the effects bus at a lower level than music; Settings has a separate weather sound slider. `tests/weather-ui.cjs` forces every type in a private world, checks indoor audio, shared state, the schedule across a restart, midnight visibility and canvas cost on a 4× slower CPU.

## Types

`clear`, `rain`, `snow`, `fog`, `thunderstorm`, `wind` and `sandstorm`. Each has an **intensity**: `light`, `medium` or `heavy`. `clear` has none. `wind` carries a **variant** that decides what it blows: `leaves`, `ash`, `dust`, `cloud`, `stardust`, `shards`, `petals` or `snow`.

## Which weather a zone may have

Every map's allowed types come from its `theme` in `world/map.txt`, through the table in `scripts/weather_zones.py`. The result is in [weather-zones.txt](weather-zones.txt); regenerate it with `python3 scripts/weather_zones.py --write`. `--check` fails when the file is stale **or when a zone has a theme with no mapping**, so a new zone cannot silently get no weather rule. The server must read the same table (`WEATHER-SERVER` ships it as data generated by this script, not a second hand-written copy).

Highlights, so the intent is clear:

- Snow only in Rimeveil, Skaldholm (beyond the glacier), Frostwake, the Cairnspine and winter on the Yearwheel; never in the desert, fen or forests.
- Sandstorms only in the Lapis Erg and the Prismwaste; ash wind in the Crags; no rain or snow in the Crags.
- Thunderstorms in Greenmeadow, Gloamfen, Wyrdwood, Bifrost Reach, the Stormglass Shore, the Tanglecrown and the Yearwheel.
- Nacrehold lies beneath a quiet tide, so it is always clear.
- The Yearwheel's type follows the **season of the quadrant the hero stands in** (spring rain, summer thunderstorm, autumn leaf wind, winter snow), using the same season map as the seasonal enemies. Crossing a boundary fades one type out and the next in over 3 seconds. The fog entry applies in every quadrant.

## Inside

No weather is ever shown, and none is simulated for the client, when the hero is **inside**. Inside means:

- a **private dungeon copy** (a map with `copies`) and every map the day-night cycle already treats as enclosed (the Obsidian Orrery, Rán's Deep, Veyrroot Heartwood and the arena);
- a **building interior or cave**: no enterable interior exists today, so there is nothing to add yet. When one is added, its map data must set `interior: true` on the region, and the server must report the hero's `inside` state in the snapshot. `scripts/weather_zones.py` must be extended at the same time.
- Zones are enclosed **as a whole**: there are no half-covered rooms in the current data, so inside is decided per map. Walking through a gate or portal into or out of an enclosed map fades the effect over **about 1 second**, the same as the day-night cycle. Rain sound and splashes stop with the fade.

## Schedule: seeded, shared, restart-proof

Weather is a pure function of **(world seed, zone number, slot number)**, with no stored state. The world seed is the existing `daynight_epoch_ms` in SQLite, so a restart continues the same weather. Every hero in a zone sees the same weather (the server sends `{type, intensity, variant, endsInSeconds}` with each zone snapshot, and clients draw it locally).

- **Slot:** 240 real seconds (4 minutes, or 4.8 game hours). Slot `n` starts at `epoch + n × 240 s`.
- **Spell length:** a spell is a run of whole slots chosen by the seed: clear lasts 2–5 slots (8–20 minutes), any other type lasts 1–4 slots (4–16 minutes). Spells never overlap and always alternate sensibly: two non-clear spells in a row are allowed only when the types differ.
- **How often:** over a long run roughly 55% of the time is clear and 45% is some weather in a zone with all types. A zone with a single allowed type is clear half the time. The server samples the seed deterministically, so the figure is checked over a long window in `WEATHER-CHECK`.
- **Intensity:** light 50%, medium 35%, heavy 15%. A spell's intensity is fixed for the whole spell, except that the first and last 20 seconds ramp it up and down so the edges are soft (the client does this).
- **Hour bias:** the day-night hour changes the weights, never the allowed types. Fog is 3 times as likely for spells that start 05:00–08:00 game time; thunderstorms are 2 times as likely 17:00–22:00; sandstorms 1.5 times as likely 10:00–16:00. Rain and thunderstorm darken the sky tint by one step of the current phase's tint, which is a client rule (`WEATHER-RAIN`, `WEATHER-OTHER`).
- **Cities:** weather applies to city zones too (Skaldholm snow and fog, the Veyrroot Canopy rain). Shops and quests are unaffected.

## Cosmetic by default

Weather changes **nothing** that the server simulates: movement speed, view distance, hit chance, damage, drops, quests and regeneration are unchanged. Lightning is a visual flash and sound only and never damages anyone. Reduced visibility in fog is visual (a vignette and a shorter drawn horizon) and the minimap and the world map stay fully readable. A later task may add small gameplay effects, but they would need their own rules, tests and a setting that turns them off.

## Controls

- **Settings:** weather effects can be turned off or lowered (`WEATHER-UI`). The setting only changes drawing; the server state and the HUD icon stay.
- **Game masters** get `/weather <type> [light|medium|heavy]`, `/weather clear` and `/weather resume`, which set a transient override for the GM's current zone (it resets on restart, like `/time freeze`). Private test worlds get the same `set_weather` debug op without a GM account, so tests can force every type.

## What `WEATHER-CHECK` must prove

- Every type appears only in zones that allow it, and none in an enclosed zone.
- The same seed gives the same weather after a restart and for every hero in a zone.
- Spell lengths and the clear/weather ratio stay within the stated ranges over a long window.
- Combat, movement and drop outcomes with weather forced on are identical to clear.

## Rain direction correction (Beta 1.32.2, same-version follow-up)

Rain and thunderstorm drops move down and to the right. Their streaks now trail
behind along that same velocity, rather than leaning down-left against the
rightward motion. The tip is the moving particle position and splash center;
streak length determines the trail time for each drop's fall speed. This is a
client-only change with no schedule, sound or server changes.

`node tests/rain-direction.cjs` passes 38 focused checks across both rain types,
all intensities and both graphics settings, comparing stroke direction with
particle motion between frames and checking splash alignment, reduced motion
and the off setting. `MUTATE=direction` restores the old streak and fails the
measured-velocity assertion.

## Camera-relative rain (same-version Beta 1.32.2 follow-up)

The field passes its projected camera to `Weather.draw`. Drops are anchored to
the world, and their streaks use rain velocity minus camera velocity: walking
into rain speeds it up; walking with it slows it down. Camera jumps and long
stalls reset motion blur, and reduced-motion precipitation remains stationary.
The focused direction test now passes 48 checks, including both walking
directions, relative streak alignment and teleport protection. `MUTATE=camera`
removes the camera offset and fails the relative-motion assertion.
